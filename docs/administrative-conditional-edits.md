# Conditional employee profile and address edits

For the Intranet admin editor, fetch `GET /employees/{employeeId}/edit` with the existing employee-read permission and resource `/employees/{employeeId}`. It returns the PascalCase employee scalar fields plus a quoted strong `ETag`. Unlike the ordinary employee GET, this projection omits related address/role objects. Changing an address or role's content does not change this employee edit version; changing HomeAddressId/RoleId does. The ordinary employee GET remains unchanged.

Address editors use existing `GET /employees/addresses/{addressId}`, which now also returns `ETag`. Both version-bearing reads use `Cache-Control: no-store`. No version is a credential or authorization grant; normal permission checks remain mandatory.

Send the exact version read with the form as `If-Match` on `PUT /employees/{id}/versioned` or `PUT /employees/addresses/{addressId}/versioned`. A successful conditional PUT returns204 and the committed new ETag. Missing preconditions return428. Well-formed stale versions return412 without saving or cache invalidation; absent rows return404; malformed, weak, wildcard or multiple validators return400. Ordinary PUT routes retain their current replacement semantics and are not protected against stale-form writes. The new Intranet editor must require the captured version, rather than silently using that compatibility path or fetching a fresh token just before saving.

Profile PUT fields are `RoleId, FirstName, LastName, PhoneNumber, Email, DateOfBirth, HomeAddressId`; omitted/null nullable values clear fields. FirstName/LastName preserve literal values from the original administrative create/update controller; all three administrative writers reject blank names, NUL, malformed Unicode and values longer than 256 UTF-16 code units before mutation. No normalization or clipping is applied, including excess trailing spaces. Email retains existing trimming, PhoneNumber retains literal administrative replacement, and the separate self-profile trimming/UTF-16 length contract is unchanged. FullName remains computed with PostgreSQL btrim U+0020; timestamps remain server-owned. Address PUT retains literal nullable fields and CountryId. Create/address attachment routes are unchanged. No schema, model, migration, Auth identity field, shared dependency pin or credentials are changed.

Conditional compare/update executes within one PostgreSQL transaction and row lock. Every execution-strategy attempt uses a fresh context. Pre-commit failures can roll back and retry; once commit is attempted, an exception is fenced from automatic retry and propagated as a generic uncertain outcome, never ordinary stale412. Caller-requested cancellation stays cancellation. The application invalidates potentially stale profile/linked-address cache independently of the caller token before propagating uncertainty or cancellation. After a known successful commit, cache invalidation follows the existing application boundary. Database failures retain normal private middleware error classification. A commit or cache failure can leave a committed write; it must not be automatically replayed or described as rolled back.

All conditional post-commit cache cleanup uses an independent token, including known success. If Redis cleanup itself fails while preserving caller cancellation, cancellation remains the outward result; cache invalidation cannot be guaranteed during that outage. Normal employee reads remain authoritative database projections and do not serve cached employee content. The consumer must reload deliberately after an uncertain outcome rather than replay the write.

Intranet owns the sequence and partial outcomes: prevalidate complete intent; update Auth identity first; only on success update/create home address; then update profile. Auth's400/404/503 and eventual identity412 are separate producer results and stop later writes. Employee's412 likewise stops the consumer. These endpoints do not call Auth, synchronize identity email, or provide a distributed transaction. A later failure may leave an earlier producer already changed. Do not claim rollback or replay uncertain writes. The supplied profile/address versions guard their own rows independently.

The tokens hash a resource-kind-bound scalar edit projection including Id and server timestamps; profile tokens contain no identity/security fields. They are not persistent columns and require no schema change. The editor must not manufacture a token or use a token from another resource.

Regression coverage uses the normal Production RS256/permission pipeline, PostgreSQL18 and Redis: two-reader stale rejection with full scalar-row/cache nonmutation; concurrent conditional writers; malformed/missing validators; wrong-resource token; missing rows;401/403; projection privacy and independence; unversioned compatibility; normal400 and database-constraint rollback. A real-PG transaction interceptor throws a transient acknowledgment failure after server commit: the response must be uncertain500, the committed change readable, potentially stale cache evicted and commit count exactly one. A companion direct application/PG regression cancels at that same boundary and verifies caller cancellation, one commit and safe cache invalidation. Hosted build, full suite, format, audit, secrets and raw coverage are required before acceptance; writing these tests is not execution evidence.
